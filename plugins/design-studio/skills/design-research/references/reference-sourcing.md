# Reference sourcing — how to mine each platform

Access model: **WF** WebFetch/browser (public) · **API** · **GH** GitHub · **LG**
login-gated (ask the user for screens). Never fabricate gated content.

## Web craft galleries (WF)
- **Awwwards** (awwwards.com) — top web craft; filter by category/color/tag. The
  bar for "does this look designed".
- **Land-book, Lapa Ninja, Landingfolio, SaaSLandingPage** — landing pages by
  category/industry; great for structure.
- **SiteInspire, Minimal.gallery, Httpster, Godly, recent.design, Curated.design,
  CSSDA, The FWA** — curated web; different taste filters.

## App UI & flows
- **Mobbin** (LG) — enormous library of real app screens + flows; the best for "how
  do real apps do X". Login-gated → ask the user to pull the specific screens.
- **Refero** (refero.design, WF/LG) — web + app reference library.
- **Page Flows** (LG) — onboarding/flow recordings.

## Type
- **Typewolf** (WF) — "fonts in use" on real sites, recommendations, lists. The
  fastest way to ground a type direction in reality.

## Visual mood (vet hard)
- **Dribbble, Behance, Pinterest, ArtStation** (WF/LG) — inspiration, but biased to
  pretty-unbuildable concept shots and increasingly AI-slop. Use for mood only;
  verify every move against a real shipping site before committing.

## Real code (GH — first-class)
- Search GitHub for component libraries, `awesome-web-design`, `awesome-threejs`,
  templates, and the actual source of any library you cite. Read the real API.

## Process
1. Define the brief + the one idea (or derive it).
2. Pull 8–15 candidates across web-craft + app + type sources.
3. Vet to 4–6 keepers with a point of view and buildability.
4. For each keeper: link + the specific move to steal.
5. Note the category clichés to avoid.
6. Synthesize into the design-direction schema.
